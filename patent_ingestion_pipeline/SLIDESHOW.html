Patent Ingestion Pipeline

Automated extraction, validation & review of patent synthesis data

Project: SynAgent Patent Intelligence System

Status: MVP Ready (May 2026)

Technology: Qwen LLM (Savio) + SQLite + FastAPI + Scrapling

The Challenge

🔍 Manual Patent Data Extraction is Slow

  • Reading patent documents one by one
  • Manually extracting reaction conditions (temperature, yield, catalyst)
  • Validating chemical structures (SMILES)
  • Cross-checking against databases

⚠️ LLMs Hallucinate Chemical Data

  • Generated SMILES may not be chemically valid
  • No automatic verification or confidence scoring
  • No human feedback loop for correction

Our Solution

An integrated pipeline that:

  • Collects patents from web (Scrapling) + PDFs (pdfplumber)
  • Parses with Qwen LLM (vLLM on Savio GPU)
  • Validates chemistry (RDKit + PubChem cross-check)
  • Scores confidence (multi-pass verification pipeline)
  • Enables human review (web UI with modal editing)
  • Logs corrections (active learning for retraining)

System Architecture

Web URLs → Scrapling → Raw Documents (SQLite) ↓ PDF Collector → pdfplumber → Extract text/tables ↓ Parse Queue → LLM Parser (Qwen/vLLM on Savio) ↓ Chemistry NER ← OPSIN, RDKit, PubChem ↓ Canonicalization & Confidence Scoring ↓ Database (SQLite) → Web UI (FastAPI + Jinja2) ↓ Human Review & Active Learning Logs

Key Features (1/2)

✓ Web Collection

Scrapling-based scraping + PDF download & text extraction via pdfplumber

✓ LLM-Powered Extraction

Qwen 27B via vLLM returns structured JSON: patent ID, reactions, SMILES, conditions

✓ Multi-Pass Validation

LLM → NER → SMILES canonicalization → PubChem cross-check → confidence score

✓ Chemistry Validation

RDKit SMILES validation, PubChem name lookup, yield/temperature/catalyst extraction

Key Features (2/2)

✓ Human-in-the-Loop UI

Web interface at http://127.0.0.1:8001 — review patents, edit reactions, log corrections

✓ Modal Editing

Click "Edit" on a reaction → modal pops up → change SMILES/notes → AJAX save

✓ Batch Review

Dedicated page for low-confidence reactions (<0.6) — efficient bulk correction

✓ Active Learning Logging

Every correction stored (reaction_id, field, old_value, new_value, user, timestamp)

Database Schema (SQLite)

Tables

  • patents — title, abstract, inventors, domain_tags, reviewed
  • reactions — product_smiles, confidence, yield, temp, catalyst
  • raw_documents — source_url, fetched_at, raw_text

Indexes & Features

  • FTS5 — full-text search on patents/reactions
  • parse_queue — async worker orchestration
  • active_learning — correction logs
  • Semantic index — FAISS (optional)

Chemistry Validation Pipeline

Confidence scoring prevents storing bad SMILES:

1️⃣ RDKit Canonicalization (60 pts)

If SMILES is valid per RDKit, extract canonical form, add 0.6 to confidence score.

2️⃣ PubChem Cross-Check (40 pts)

Query PubChem for canonical SMILES. If agreement, add 0.4.

3️⃣ Confidence Score

Final: 0.0–1.0. Reactions <0.6 are flagged for human review.

Running on Savio (Berkeley Lab)

vLLM Setup

  • Qwen 27B running in Apptainer (Docker image)
  • vLLM exposes OpenAI-compatible /v1/chat/completions API
  • Slurm job: 1 GPU (A40), partition savio3_gpu, 2 hours

Access from Local Machine

  • SSH tunnel: ssh -L 8000:compute_node:8000 user@savio.lbl.gov
  • Local .env points to http://127.0.0.1:8000
  • Worker calls LLM transparently via HTTP

CLI Commands

# Initialize database python -m patent_pipeline.cli init_db # Collect patents python -m patent_pipeline.cli collect "https://..." python -m patent_pipeline.cli collect_many urls.txt # Enqueue for parsing python -m patent_pipeline.cli enqueue_all # Run worker (polls queue, calls LLM) python -m patent_pipeline.cli run_worker \ --base-url http://127.0.0.1:8000 \ --model qwen # Start web UI python -m patent_pipeline.cli runserver \ --host 127.0.0.1 --port 8001
